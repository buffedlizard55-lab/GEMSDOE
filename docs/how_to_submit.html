3. Four routes to that file

RouteCostExact commandWhat you get
AUse the committed ensemble artifactseconds
curl -L -o submission.tif https://github.com/buffedlizard55-lab/GEMSDOE/raw/main/data/evidence/runs/ens12-adopted-floor0.1-w0/submission.tif
The 11-fold blend with the adopted emission policy. Format-validated by the committed validator log; its quality numbers are on results.
BRe-run the training workflow on GitHub Actions2–6 h, free
gh workflow run train-and-submit.yml -f profile=smoke   # or: Actions → Train and build submission → Run workflow
Uses the CPU runner as the unrestricted machine: assembles data/ from the bridge, trains, infers, validates, scores, and publishes submission.tif as a workflow artifact.
CGenerate one locally, CPU-only, no GPU≈ 20 min
python scripts/baseline_submission.py
Classical classifier on the official 19 bands. It holds out two folds: one selects the emission policy on the union population, the other measures the winner untouched, so the quoted number is not the maximum of the numbers it was chosen from. Writes the raster, its .sha256 sidecar and a report that refuses to claim competitiveness. A floor, not a contender — see the caveat below.
DFull-capacity GPU training≈ 1 h on a 24 GB GPU
python -m src.train --config configs/config.yaml && python -m src.inference --config configs/config.yaml --out submission.tif
The reference-scale configuration (10 MC splits, 60 epochs, EfficientNet-B5). Needs a GPU box; not required for a valid first submission.

4. Validate before uploading (the gate that catches a silent format break)

python scripts/validate_submission.py --pred submission.tif     --sample data/sample_submission.tif --train data/training_features.tif

5. Uploading, click by click

  1. Join the competition — competition home → create a DrivenData profile → accept the rules.

    “To enter the competition, you must create a profile on the DrivenData platform and agree to abide by the competition rules and restrictions.”
    — official rules §3.1 · VERBATIM MATCH docs.nlr.gov/docs/fy26osti/96647.pdf · sha256 50d854b1e0239fe6… · checked by scripts/verify_rules_quotes.py 2026-09-19 · why it matters: The one genuinely human step: registration, then the account-gated data tab and upload.

  2. Open the Submit tab — …/competition-doe-gems/submissions/ — the platform shows the quota it will enforce.

    “You can make multiple submissions, subject to the limits specified on the competition website (three submissions per week).”
    — official rules §3.2 · VERBATIM MATCH docs.nlr.gov/docs/fy26osti/96647.pdf · sha256 50d854b1e0239fe6… · checked by scripts/verify_rules_quotes.py 2026-09-19 · why it matters: Three measured shots per week at the real metric - the only honest feedback available.

  3. Upload the .tif — One file, unzipped, single band. The platform validates the format on receipt and returns either a score or a format error.

    “You must submit a single GeoTIFF with a single raster layer at 100-meter resolution containing your model's predictions of fault locations for the entirety of the GeoDAWN study area.”
    — official rules §3.2 · VERBATIM MATCH docs.nlr.gov/docs/fy26osti/96647.pdf · sha256 50d854b1e0239fe6… · checked by scripts/verify_rules_quotes.py 2026-09-19 · why it matters: Submission format, exactly.

  4. Read the returned score — Public scores appear on the leaderboard; the headline number to beat was 0.1972 over 43 ranked entrants when this repository last read it (2026-09-16).
  5. Keep exactly one entry — Before the deadline, designate the single submission that is scored across both prize rounds — the same file, re-scored against the revised label set.

    “Before the end of the competition, you must choose only one submission for evaluation across both prize rounds.”
    — official rules §3.5 · VERBATIM MATCH docs.nlr.gov/docs/fy26osti/96647.pdf · sha256 50d854b1e0239fe6… · checked by scripts/verify_rules_quotes.py 2026-09-19 · why it matters: One artefact must serve both rounds; nothing can be tuned for one and swapped for the other.

6. After the upload

  • Record the sha256 you uploaded next to the leaderboard score the platform returns: that is the only unbiased number this project has ever had (every local number is a surrogate, on results).
  • Diarise the final selection. Deadline as recorded in docs/data_catalog.csv row C1: Dec 3 2026 11:59pm UTC — verified 2026-09-12 by fetch_page (VERIFIED - full text retrieved) from the competition home page. Confirm it on the platform: the catalogue is a dated snapshot, not a live feed.
  • The same file is re-scored in Phase 2 against the expert-revised new-fault set.

    “Submissions will be reevaluated against the full, revised new fault dataset using the same distance-weighted Tversky index.”
    — official rules §1.1 · VERBATIM MATCH docs.nlr.gov/docs/fy26osti/96647.pdf · sha256 50d854b1e0239fe6… · checked by scripts/verify_rules_quotes.py 2026-09-19 · why it matters: Phase 2 is the same metric on the same population - one objective, two label revisions.

8. The CPU route, and its own caveat

A submission that scores badly is still information; a submission that is never uploaded is not. Route C exists so a valid entry is possible from any machine in the project, and its own report refuses to claim competitiveness. Route A is the artifact to upload first.
