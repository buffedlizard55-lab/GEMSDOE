Why Reference Solution is Insufficient

From reference solution notebook unet-mc-cv-reference-solution.ipynb:

  • Single U-Net, 5 MC splits, patch 128, 5 epochs, basic [0,1] min-max norm
  • No external DEM, no TTA, no ensemble, no post-processing, no robust norm
  • No distance weighting in the loss, no submission shaping, and no scoring code at all: the notebook tracks only TverskyLoss values. The distance-weighted Tversky index is described on the problem page but is not implemented anywhere in the reference repo (verified by reading every cell of unet-mc-cv-reference-solution.ipynb, 21 cells, cloned 2026-09-12)
  • Cosmetics that matter: it writes predicted_faults_example.tif without NaN outside the valid footprint and without clipping to [0,1] (cell 19 copies crs/transform only)

We do not publish an expected DTI. There is no public history for this competition to calibrate against, so any such number would be invented. What we publish instead is measured on real public data and reproducible: the verification log (metric equivalence tests, the shaping experiment worth 2.8× on a smoke model, and a 3-arm loss A/B). The public leaderboard (3 submissions/week max, rules §3.4) is the first unbiased signal.

Data Engineering — Verified Sources

Normalization (stats persisted, so train == inference == reproduction)

Per channel: 1–99 percentile clip → robust z-score → [0,1], NaN→0. The reference solution's plain min–max over the whole raster ((X - nanmin)/(nanmax - nanmin), cell 5) is not robust to the heavy-tailed magnetic/gravity bands; we keep mode: minmax available for A/B. Statistics are written to outputs/norm_stats.json at train time and re-loaded at inference (fit_norm_stats / apply_norm_stats in src/dataset.py) — required by rules §3.5 ("sufficiently reproduce the winning results").

External DEM Features from 3DEP

Official source: USGS 3DEP https://www.usgs.gov/3d-elevation-program/about-3dep-products-services + Downloader https://apps.nationalmap.gov/downloader/ + LidarExplorer https://apps.nationalmap.gov/lidar-explorer/ + AWS https://registry.opendata.aws/usgs-lidar/

From 1m DEM (via 1m_DEM_links.csv), resampled to 100m, compute:

  • Slope: arctan(sqrt(dx²+dy²)) *180/π via np.gradient
  • Curvature: second derivative dxx+dyy
  • TPI: Topographic Position Index = dem - mean(dem in radius)
  • TRI: Terrain Ruggedness Index = mean abs diff to 8 neighbors
  • Hillshade: sin(alt)*sin(slope)+cos(alt)*cos(slope)*cos(az - aspect)
  • Detrended: dem - Gaussian smoothed (sigma 50)

Implemented in src/external_data.py. These augment provided features; faults often correlate with topographic lineaments.

Patching

Reference design (cells 11–12): cut non-overlapping test windows, zero them in the global raster, then re-patchify with a smaller train step — we keep that order of operations exactly, because the previous version of this repo kept training windows that partially overlapped test labels (CV optimism; flagged in review, now fixed and pinned by test_patches_have_no_label_leakage).

  • train windows need ≥3 fault pixels; empty windows kept at neg_fraction (0.35–0.4) so the model learns the background — the reference trains only on fault-bearing windows, which is why its outputs are diffuse
  • per-patch FP weight map = 1 − max_g k(d(x,g)), cropped from the global EDT, so a prediction at a patch border is neither rewarded nor punished by the crop
  • patch 256 (config) vs 128 in reference: faults here are km-scale lineaments and need wider context

Implemented in src/dataset.py:make_patches().

Augmentation

Implemented in src/dataset.py:FaultDataset (numpy, applied identically to x, y and the FP-weight map, so alignment is guaranteed and no torchvision dependency is needed): random crop 0.75–1.0 with re-padding (crop rather than resize, because a fault trace is 1 px wide at 100 m and resampling erases it), horizontal flip, vertical flip, k×90° rotation, Gaussian noise σ=0.01. The reference uses v2.RandomResizedCrop + RandomHorizontalFlip + RandomVerticalFlip + RandomRotation(30) — the same family, and our rotation set is exactly the set our TTA inverts.

Model Architecture — Ensemble

Uses segmentation_models_pytorch https://github.com/qubvel/segmentation_models.pytorch

  • Encoders: EfficientNet-B3/B5, ResNet-50, MIT-B2 (SegFormer) pretrained on ImageNet
  • Decoders: UNet++, DeepLabV3+, SegFormer, FPN
  • Loss: 0.3 BCE + 0.5 (1 − DTI_surrogate) + 0.2 focal-Tversky. The DW term is a differentiable transcription of the official metric (R=3 px kernel, α=0.2, β=0.8) and is asserted equal to 1 − DTI of the scorer by tests/test_metric.py::test_dw_loss_is_the_metric — src/losses.py
  • Training: 10 MC splits (70/30), AdamW lr 1e-4 → OneCycleLR peak 1e-3, batch 16, 60 epochs, AMP on CUDA, model selection on shaped held-out DTI, one architecture per split; artefacts and the calibrated shaping pair land in outputs/manifest.json
  • Submission shaping: floor + distance-R dominating thinning, parameters searched on pooled held-out windows (src/submission_optim.py) — the FP term is an area sum, so this is worth more than any architecture change we measured
  • Inference: Sliding window 50% overlap + Gaussian blending, TTA 8 flips/rotations, ensemble averaging across MC splits and architectures — src/inference.py

Why ensemble? Different architectures capture different fault scales: UNet++ for fine details, DeepLabV3+ for multi-scale context (atrous), SegFormer for global attention.

Post-Processing for Final Round — Discover New Faults

From about page https://www.drivendata.org/competitions/306/competition-doe-gems/page/968/ and papers:

  • Mattéo et al 2021 Automatic fault mapping in remote optical images and topographic data with deep learning https://doi.org/10.1029/2020JB021269
  • Hermant et al 2025 Using deep learning to map Quaternary faults in Western USA https://pangea.stanford.edu/ERE/db/GeoConf/papers/SGW/2025/Hermant.pdf

Steps in src/postprocess.py:

  • Low threshold 0.1-0.2 to maximize recall (β=0.8)
  • Frangi filter for line enhancement (vesselness)
  • Morphological closing to connect fault segments
  • Skeletonization optional, dilation to connect
  • Length filtering min 5px to remove noise
  • False positive control: mask with slope & curvature thresholds

For Final Round, we want high recall — predictions that helped experts identify previously-unmapped faults score higher. So we keep low threshold, enhance lines.

Metric Implementation — Exact Reproduction

From problem page https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/#performance-metric

Our src/metrics.py implements distance-weighted Tversky exactly:

k(d)=max(1-d/R,0), R=300m=3px
TP_w = Σ_g max_{x:d≤R} p(x)k(d)
FP_w = Σ_x p(x)[1-max_g k(d)]
FN_w = Σ_g [1-max_{x:d≤R} p(x)k(d)]
DTI = TP_w/(TP_w+αFP_w+βFN_w+ε)
α=0.2 β=0.8

Uses scipy distance_transform_edt for FP weighting and view_as_windows 7×7 max filter for TP/FN. Tested: perfect line → 0.91 DTI, shifted 1px → 0.61 DTI (distance weighting tolerates misalignment), empty → 0.0.
