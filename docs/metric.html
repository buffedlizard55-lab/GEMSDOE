Metric

The scoring function, rearranged — and what it actually pays for.

Definition

Scoring is a distance-weighted Tversky index with α=0.2, β=0.8 and a triangular kernel of range R=300 m (3 px at 100 m) — official definition. Our implementation is src/metrics.py; its self-test checks it against a brute-force transcription of the formulas and reproduces the worked example's 0.60.

TP_w = Σg∈G maxx:d(x,g)≤R p(x)·k(d(x,g))
FP_w = Σx:p(x)>0 p(x)·[1 − maxg∈G k(d(x,g))]
FN_w = Σg∈G [1 − maxx:d(x,g)≤R p(x)·k(d(x,g))]
DTI  = TP_w / (TP_w + α·FP_w + β·FN_w + ε)

The rearrangement that matters

From the two sums, TP_w + FN_w = |G| holds identically, for any prediction. Substituting:

DTI = TP_w / ( 0.2·(TP_w + FP_w) + 0.8·|G| )

So TP_w and FP_w enter with the same coefficient. Probability mass costs the same wherever you put it; it earns credit only when it is the strongest mass within 3 px of a ground-truth pixel. And TP_w saturates at 1 per ground-truth pixel, so extra mass on an already-covered fault is pure cost. scripts/metric_strategy.py asserts this identity against the direct computation on every row below.

The counter-intuitive result. α=0.2 / β=0.8 reads as “false negatives hurt 4× more, so predict generously”. The measurement says the opposite: blanket coverage scores 0.096, while a precise quarter of the faults scores 0.554 — about 6× better from 200× less predicted mass. β multiplies FN_w, which is capped at |G|; α multiplies FP_w, which grows with the area you paint, and there are ~50× more non-fault pixels than fault pixels. The per-unit discount loses to the count.

Consequences for the model

  • Be sparse, thin and confident. Dilating perfect predictions by one pixel costs 12 points of DTI (0.9999 → 0.8818); by three pixels, 41 points.
  • Thin, but not to nothing. Faults are 1-px lineaments at 100 m and src/submission_optim.py applies a probability floor plus distance-R dominating thinning; the pooled search selects thin=True essentially always. But the width of what is kept is a separate decision, and against the public labels it is not zero — see the measured width curve.
  • Recall still matters most among correct predictions — DTI is near-linear in the fraction of faults found (0.554 → 0.794 → 0.917 for 25/50/75% precise recall).
  • Beat 0.096. A model scoring under the blanket-coverage floor is worse than a constant.

How wide should the line be? — measured

TPw takes a max within R = 3 px, so a prediction up to that far from a label still earns full credit, while FP costs 0.2 per unit of mass and a missed label costs 0.8. That makes the width of the emitted line a first-class decision: a skeleton scores zero on a fault it missed by more than R, while a band of k pixels survives k px of localisation error. The scored faults are new to the expert-reviewed dataset (rules §1.1/§3.5) and the model has never seen them, so its localisation error there is strictly larger than on the catalogue.

What this is and is not. The labels here are the public catalogue, not the scored set, and shifting them is a stress test of the writing operator, not a measurement of the competition metric. It is reported because the same asymmetry applies with more force to faults the model has never seen.
Because of this the shaping search now searches the emission width too (--dilate-grid), and --calibrate loo re-fits the floor on the folds that are not being scored, so the reported mean is not selection-optimistic.

What the metric is actually computed against

Both prize phases are scored on the new fault dataset — faults that are not in the public catalogue the competition hands out for training. The training labels are the existing fault data. The two populations are disjoint by construction, which is the single most consequential fact in this competition:

Consequence for everything else in this repository. A model that reproduces labels.tif perfectly scores ~1.0 against the catalogue and ~0 against the competition target: the scored faults are precisely the ones missing from the catalogue. So the catalogue DTI quoted throughout this site is a plumbing monitor, not a leaderboard proxy — useful because it proves the metric, the loss, the tiling and the writer agree, and not useful for choosing between models. The quantities that speak to the real objective are in src/discovery.py: novel_fraction (share of emitted probability mass farther than R from any catalogued fault) and candidate_new_faults (connected components of the prediction that touch no catalogued fault). A submission of pure noise also has novel_fraction ≈ 1, so those diagnostics are never read alone — they are read next to the catalogue DTI, the emitted area and the component sizes.

Remaining caveats

  • |G| for the hidden test set is unknown, so the 0.8·|G| floor is unknown. Every absolute DTI on this page is a monitor; only ratios and identities carry over.
  • ε is not specified on the problem page; we use 1×10⁻⁷. Negligible here, recorded for exactness.
  • The public leaderboard is scored on a public split of the same new-fault dataset, so it is the first honest signal; the private split and the Phase-2 revision are hidden.
