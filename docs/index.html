1. Overview — What is GEMS Prize?

Source: Competition Main | Problem Description | About Page | Official Rules PDF

Goal (from problem page): Develop models and algorithms that provide accurate information about presence of structures indicative of geothermal resources — namely, geological faults. A unique feature: ground truth for currently known faults is publicly available! But it is incomplete and may contain inaccurate data. New faults manually identified by experts comprise test dataset for initial prize round. After initial round, expert panel uses submitted predictions to update fault labels for full region. Submissions rescored against entire updated label set for final round awards.

Why Faults Matter

From About Task: Geological fault is fracture where two blocks have measurable displacement. Plane = fault plane, intersection with surface = fault trace. Multiple related fractures = fault zone. Detected via field observations, geophysical surveys (seismic reflection, gravity, magnetic), remote sensing, elevation, edge detection, Hough transforms, deep learning.

Geothermal resources often found in regions with active/recent faulting where fractures provide pathways for hot fluids. Image: Steamboat Geothermal Plants near Reno, Nevada (within GeoDAWN) — public domain via Wikimedia Commons (linked on about page).

3. Metric — Distance-Weighted Tversky Index

Source: Performance Metric | Formula verified line-by-line from page chunk 1.

Tversky index is similarity metric parameterized by α (FP penalty) and β (FN penalty). For this challenge: α=0.2 (low FP penalty), β=0.8 (high FN penalty) → rewards high recall. Rasterization lossy, fault misalignment possible → weight by distance to nearest ground truth using triangular kernel with 300m support (3 pixels at 100m).

Mathematical Representation (from page)

Let p(x)∈[0,1] = predicted prob at pixel x
Let g(x) = ground truth label

TI(α,β) = Σ p(x)g(x) / [Σ p(x)g(x) + α Σ p(x)(1-g(x)) + β Σ (1-p(x))g(x)]

Triangular kernel k(d) = max(1 - d/R, 0), R=300m = 3px

TP_w = Σ_{g∈G} max_{x:d(x,g)≤R} p(x) k(d(x,g))
FP_w = Σ_{x:p(x)>0} p(x) [1 - max_{g∈G} k(d(x,g))]
FN_w = Σ_{g∈G} [1 - max_{x:d(x,g)≤R} p(x) k(d(x,g))]

DTI(α,β) = TP_w / (TP_w + α FP_w + β FN_w + ε)

α=0.2, β=0.8, ε small

Implementation: src/metrics.py uses distance_transform_edt for FP weighting and 7×7 max filter for TP/FN (R=3 → window 2R+1=7).

Scoring Example (from page)

From page: Ground truth single vertical line, triangular kernel R=3 applied. Illustration shows weighted contributions. Example calculation: TP_w=3.00, FP_w=1.89, FN_w=2.00 → TI_w(α=0.2,β=0.8)=3.00/(3.00+0.2*1.89+0.8*2.00)=0.60

6. Method — How to Place Top of Leaderboard

Reference Solution (Baseline)

Author: John Lipor, Portland State — GitHub

  • U-Net with segmentation_models_pytorch
  • 5 MC splits, patch 128, 5 epochs, Tversky loss α0.2 β0.8, basic [0,1] min-max norm
  • Single model, no TTA, no external DEM, no post-process
  • Rough DTI estimate only (clearly labeled estimate; no verified public baseline exists for this new competition)

Notebook: unet-mc-cv-reference-solution.ipynb — loads features, patchify, train U-Net, average predictions.

Our Improvements — Top Leaderboard Target

  • Data: Robust percentile clipping (2-98%) + standardization, not just [0,1]. DEM augmentation: slope, curvature, TPI, TRI, detrended, hillshade from 3DEP via src/external_data.py (official source https://www.usgs.gov/3d-elevation-program/about-3dep-products-services)
  • Patches: 256px (larger context) + train_step 32 overlap, hard-negative mining (30% negatives kept)
  • Aug (planned — NOT yet wired into the train loop, flagged 2026-09-12): RandomResizedCrop 0.5-1.0, flips, rotations, elastic, Gaussian noise — FaultDataset.transform is currently a no-op placeholder
  • Models: Ensemble UNet++, DeepLabV3+, SegFormer with EfficientNet-B5 & MIT-B2 pretrained on ImageNet (via segmentation_models_pytorch)
  • Loss: BCE + Tversky + Focal Tversky combo matching metric α0.2 β0.8 — src/losses.py
  • Train: 10 MC splits, 50 epochs, AdamW, ReduceLROnPlateau, early stopping on DTI, mixed precision — src/train.py
  • Infer: Sliding window 50% overlap + Gaussian blend, 8-way TTA (rot + flip), ensemble average — src/inference.py
  • Post: Frangi vesselness filter for line enhancement, morphological closing to connect segments, low threshold 0.15 for high recall (β=0.8) — src/postprocess.py — inspired by Mattéo et al 2021 https://doi.org/10.1029/2020JB021269 and Hermant et al 2025 https://pangea.stanford.edu/ERE/db/GeoConf/papers/SGW/2025/Hermant.pdf

Architecture Diagram

Input: (H,W,C) multi-geophysics (15 bands) + DEM derivatives (slope, TPI, TRI, curv, detrended, hillshade) = ~20 channels
  ↓ robust_normalize: 2-98% clip + (x - min)/(max-min) per channel, NaN→0
  ↓ patchify: 256px, train_step 32 overlap, filter valid (mean>1e-6), 30% negatives
  ↓ Augment: RandomResizedCrop, flips, rot30°, elastic, noise
  ↓ Models (ensemble, cycle per MC split):
     - UNet++ EfficientNet-B5 ImageNet
     - DeepLabV3+ EfficientNet-B5
     - SegFormer MIT-B2
     - FPN EfficientNet-B5 (optional)
  ↓ Loss: BCE 0.5 + (Tversky 0.5 + FocalTversky γ0.75 0.5)*0.5, α=0.2 β=0.8
  ↓ Val: distance-weighted Tversky R=300m (3px) via scipy distance_transform_edt + 7x7 max filter
  ↓ Early stopping patience 7 on val DTI
  ↓ Inference: sliding window 50% overlap, batch 16, TTA 8 (4 rot × 2 flip), ensemble average
  ↓ Post: Frangi scale_range [1,10], closing kernel 3, connect faults, filter small <5px, low thresh 0.15 → prob map
  ↓ Save: GeoTIFF EPSG:32611 100m float32 [0,1] same bounds as sample/training, LZW compress
  ↓ Validate: scripts/validate_submission.py checks CRS, res, bounds, dtype, range

Why This Wins Final Round

Final Round rewards discovering true new faults that experts verify. Our low threshold (0.15) + Frangi line enhancement + DEM lineaments (slope, TPI) increases recall of subtle hidden faults not in USGS database. We don't overfit to known faults only — we use MC CV and high recall loss to generalize. Expert review builds the expanded label set from "expert review of all submissions" (competition main page, verbatim — verified 2026-09-12; problem page + PDF 3.6.1 wording: uses submitted predictions) — our predictions that flag true hidden faults become part of expanded label set and boost our Final Round score even if Initial Round was lower.

End-to-end verified 2026-09-12 (CPU): the full chain train → inference → format validation → DTI scoring was executed on a reconstructed public-source dataset (data/reconstructed/, built by scripts/build_reconstruction_dataset.py from official USGS GeoDAWN + INGENIOUS sources because the official files are login/egress-gated here). validate_submission.py result: ✅ PASSED (EPSG:32611, 100 m, float32, [0,1], grid match). Setup

git clone https://github.com/buffedlizard55-lab/GEMSDOE.git
cd GEMSDOE

# Env (choose one)
conda env create -f environment.yml
conda activate gemsdoe
# or
pip install -r requirements.txt

# Data (manual download from data tab)
mkdir -p data/
# Download from https://www.drivendata.org/competitions/306/competition-doe-gems/data/
# training_features.tif, labels.tif, sample_submission.tif, 1m_DEM_links.csv

# Optional external (verified links)
bash scripts/download_external.sh
python scripts/prepare_data.py

# Dummy submission for testing format (no training needed)
python scripts/generate_dummy_submission.py --out submission_dummy.tif
python scripts/validate_submission.py --pred submission_dummy.tif

Train & Inference (needs GPU)

# Train ensemble (MC=10, 50 epochs)
python -m src.train --config configs/config.yaml
# Output: outputs/model_mc0_unetplusplus_dti0.xxxx.pt etc.
# Plus ensemble_summary.txt

# Inference with TTA + ensemble
python -m src.inference --config configs/config.yaml \
  --model-dir outputs --out submission.tif

# Validate
python scripts/validate_submission.py \
  --pred submission.tif \
  --sample data/sample_submission.tif \
  --train data/training_features.tif

# Evaluate if you have val labels
python -m src.metrics --pred submission.tif --true data/labels.tif

# Submit via DrivenData:
# Go to https://www.drivendata.org/competitions/306/competition-doe-gems/
# Click Submit → Make new submission → upload submission.tif
# Before Dec 3 2026 11:59pm UTC, select ONE as final
