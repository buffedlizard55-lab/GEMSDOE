What to Submit — Verified from Problem Page

Source: https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/#submission-format

  • Single GeoTIFF file containing predictions for all faults in region
  • Same CRS: UTM zone 11N EPSG:32611 https://epsg.io/32611
  • Same resolution: 100m
  • Same bounds as training data, outside bounds null/nan
  • Single layer, float32, values [0,1] probability
  • Sample submission provided on data tab https://www.drivendata.org/competitions/306/competition-doe-gems/data/ (login required)

Our validation: scripts/validate_submission.py checks all above.

Dummy generator: scripts/generate_dummy_submission.py creates valid GeoTIFF for testing without training data.

How to Enter — From PDF Sections 3.1, 3.2

Source: https://docs.nlr.gov/docs/fy26osti/96647.pdf

  1. Create DrivenData account at https://www.drivendata.org/competitions/306/competition-doe-gems/ and agree to rules
  2. Navigate to challenge website to sign up as competitor
  3. Review materials: problem description https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/ and about https://www.drivendata.org/competitions/306/competition-doe-gems/page/968/
  4. Download training features + labels from https://www.drivendata.org/competitions/306/competition-doe-gems/data/ (login)
  5. Training features: GeoDAWN + other geospatial at 100m, multiband GeoTIFF, plus DEM at 1m instructions. Source: GeoDAWN DOI https://doi.org/10.5066/P93LGLVQ and 3DEP https://www.usgs.gov/3d-elevation-program/about-3dep-products-services
  6. Training labels: existing fault data at 100m, from INGENIOUS DOI https://doi.org/10.15121/1881483 (PDF footnote 4: Ayling et al 2022)
  7. Submit predictions as GeoTIFF 100m for entirety of GeoDAWN study area
  8. Generative AI disclosure required if used (PDF 3.2) — indicate in narrative extent and how used, responsible for accuracy

Feedback & Limits — PDF 3.4

⚠️ Discrepancy flagged: earlier instruction said 2 per 7 days; PDF §3.4 verbatim = "up to three per week". PDF/website authoritative — details in SUBMISSION_GUIDE.md §3.

  • Up to 3 submissions per week for automated scoring
  • Must select only one as final before deadline Dec 3 2026 11:59pm UTC (from main page https://www.drivendata.org/competitions/306/competition-doe-gems/)
  • Multiple finalized not allowed, one final per entity
  • Individuals on team not allowed separate final submission

Evaluation — PDF 3.6

  • Metric: distance-weighted Tversky index https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/#performance-metric — penalizes FN more than FP
  • Public test → public leaderboard, Private test → Initial Round $50k
  • Second-round score is against the updated test dataset created by geology experts after close (PDF 3.6.1 verbatim); per the about page, expert review uses submitted predictions to update the fault-label set for the full region
  • Final Round $250k scored against expanded set — 1st $100k, 2nd $70k, 3rd $40k, 4th $25k, 5th $15k
  • Must choose final without knowing private scores (PDF 3.6.2) — encourages generalization
  • Set of faults in the public test dataset and relative weight of faults in both test datasets determined by organizers before start (PDF 3.6.2)
  • Winners must submit complete code + docs reproducible, per Winning Model Documentation Template, plus eligibility certs (PDF 3.2, 3.5)
  • DOE is judge and final decision maker, may award all, none, or some (PDF 3.6.4, Appendix A)
  • Interviews may be held after announcement (PDF 3.6.3)

Practical Submission Steps

git clone https://github.com/buffedlizard55-lab/GEMSDOE.git
cd GEMSDOE
conda env create -f environment.yml && conda activate gemsdoe
mkdir -p data/
# Download from https://www.drivendata.org/competitions/306/competition-doe-gems/data/
# training_features.tif, labels.tif, sample_submission.tif, 1m_DEM_links.csv

# Train (needs GPU)
python -m src.train --config configs/config.yaml

# Inference
python -m src.inference --config configs/config.yaml --model-dir outputs --out submission.tif

# Validate
python scripts/validate_submission.py --pred submission.tif --sample data/sample_submission.tif --train data/training_features.tif

# Submit
# Go to https://www.drivendata.org/competitions/306/competition-doe-gems/
# Click Submit → Make new submission → upload submission.tif
# Check public LB
# Before Dec 3 2026, select ONE as final for both rounds

# If finalist, prepare code + docs per template + eligibility certs
# See PDF https://docs.nlr.gov/docs/fy26osti/96647.pdf Sections 3.2, 3.5, Appendix A

Generative-AI Disclosure Obligation (PDF §3.2 — applies to US)

This project is developed with an AI coding agent. Per PDF §3.2 (rules), if generative AI is used, the submission narrative must disclose the extent and manner of use (disclosure not counted in word limit); the competitor remains responsible for accuracy, authenticity, and authorship. Plan: include a short genAI-use statement in the submission narrative and, if finalist, in the code documentation.
