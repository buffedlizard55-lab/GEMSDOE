3. Metric calculus — the algebra that decides submission shape

From the official formulas, three consequences follow that the reference solution does not exploit (it writes raw probabilities; its own cell 17 only hints "it may be advantageous to threshold").

  1. FPw is a sum over area, |G| is a count of line pixels. Faults are ~1.4 % of pixels in the public-source reconstruction, so diffuse probability fields are destroyed: DTI ≤ TP_w/(0.2·FP_w). Measured: a mean-p=0.20 field over 326 kpx gave FPw=32 872 against |G|=968 → DTI 0.044.
  2. TPw is a MAX over the R-neighborhood. One p=1 pixel within 3 px of a ground-truth pixel earns essentially all the credit that pixel can earn; the 4–12 parallel pixels of the same corridor add nothing to TP while each adds 0.2(1−k) to FP. → thin the prediction, do not dilute it.
  3. Marginal rule. Adding probability v at pixel x (when it becomes the argmax for some g) changes DTI by v(k·D − 0.2·N)/D², so it pays iff k > α·DTI. At DTI=0.6 that is d < 2.64 px; beyond R=3 px it never pays unless the pixel truly is GT. → a "just-in-case halo" around an already-covered fault is pure cost; a corridor toward a suspected-but-unlabelled fault is nearly free. This is the lever for the Final Round (expert review rewards genuine new discoveries, §3.6 of the rules PDF).

Consequence implemented in src/submission_optim.py: hard floor (zero, not shrink) + distance-R dominating thinning, with the single (t0, thin) pair chosen by pooled held-out search during training and stored in manifest.json for inference.

Reading: at this budget the metric-aligned objectives beat the reference's pixel-wise Tversky on the shaped held-out metric (+38 % and +27 % relative). Shaping helps every arm (+97 % / +113 % / +54 % relative to its own raw field), which is the robust part of the result.

Two columns, two different questions — read them separately. dw_tversky is ahead in all three per-split values (0.1176>0.1168, 0.1049>0.0976, 0.1229>0.1215) yet loses the pooled column (0.0838 vs 0.0913). That is not a contradiction: the per-split column is each split's own best-epoch selection value, whereas the pooled number comes from a single floor/thin pair searched jointly over all splits' windows (t0=0.146 for combined_dw, t0=0.334 for dw_tversky), and a calibration that transfers across splits is what the leaderboard needs. So the honest summary is: both DW arms beat the reference criterion; which DW arm wins depends on whether you evaluate per split or with one pooled submission transform — not settled at this budget. (An earlier revision of this paragraph said dw_tversky "wins two of three splits"; that was wrong against the artifacts and is corrected here.)

7. Documentation is audited by a script, not by reading alone

Two defects found during this review were of a class that prose review misses: docs cited data/dem_links.json and data/evidence/dem_links_pdf_chunk0.txt, which .gitignore (data/*, allow-listing only README.md) had kept out of the repository, so the links pointed at nothing; and a citation in the catalog carried a wrong page range (Into the Noddyverse is ESSD 14, 381–392, not 381–416 — 10.5194/essd-14-381-2022, re-read on the publisher page 2026-09-12).

scripts/audit_docs.py (stdlib only) now checks this mechanically, and it gates the Pages deploy in .github/workflows/pages.yml:

  • every data/…, docs/…, src/…, scripts/…, outputs/… path cited in any *.md or docs/*.html must exist, or be produced by a command named in the script’s GENERATED table (so data/labels.tif may be cited as “download first”, but a citation with no producing command fails the build);
  • the data catalog must have unique ids and, per row, an https link, a verification method, an in-past date, and a result ≥10 chars; a row whose method is linked-from… must say VERIFIED INDIRECTLY rather than reading like a direct check — 11 rows were relabelled that way, and a link to a page the sandbox cannot reach is stated as such;
  • every linked host must appear in the catalog, the bibliography, or the documented CONTEXT_HOSTS table with a reason.
python scripts/audit_docs.py        # exit 1 = a doc claim is not backed by a file or an audit row
